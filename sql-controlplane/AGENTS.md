# Coding Agent Instructions

This folder is the **SQL Control Plane**: a FastAPI backend, a React UI, a stdio MCP server, and a **Microsoft
Foundry hosted agent** (`sql-ha-agent`, Agent Framework, Responses protocol). All four share the `sqlha` core
library and monitor and patch SQL Server Always On AGs managed through Azure Arc. The hosted agent was built with
the microsoft-foundry skill. Before working on or answering questions about Foundry agents, read the
microsoft-foundry skill first. If you are in VS Code, read the vscode-microsoft-foundry skill first.

## Layout and conventions

- **Core** (`core/sqlha/`, package `sqlha-core`): the only place that talks to Azure. `tools.py` is the single tool
  registry for the MCP server (`mcp_server.py`) and the agents (`agent.py`). Add a tool there once, keep the
  `sqlha_` prefix, and update the matching skill in `../.github/skills/`.
- **Backend** (`backend/app/`): keep layers thin and separate.
  - `api/routes/*` holds HTTP concerns only.
  - `services/*` wraps the core: `SqlManagementService`, `DashboardService`, `ChatService`.
  - `schemas/*` holds the Pydantic models that drive Swagger.
  - `errors.py` maps exceptions to the `{"error": {...}}` envelope.
  - New endpoints need a response model, a tag, and a test in `backend/tests/test_api.py` using fake services.
  - `POST`/`DELETE` routes must depend on `ClientGuard` (the `X-SQLHA-Client` header, which acts as CSRF protection).
- **Frontend** (`frontend/src/`):
  - All HTTP goes through `api/client.ts`, and types live in `api/types.ts` (mirroring the backend schemas).
  - Reusable pieces go in `components/common`, one view per tab in `views/`, and shared state in
    `context/DashboardContext`.
  - No `dangerouslySetInnerHTML`. `Markdown.tsx` renders through React elements.
- **Hosted agent** (`src/sql-ha-agent/`): `sqlha/` and `skills/` are generated by `scripts/sync-agent.ps1`
  (git-ignored). Don't edit the copies. Skills live in `../.github/skills/sql-ha-*/SKILL.md` (source of truth).
- Write tools must stay behind `SQLHA_ENABLE_WRITE_ACTIONS` and `confirm=true`, and must keep the AG safety checks
  (never patch the primary or both replicas together, never fail over to a replica that isn't failover-ready).
  Non-idempotent ARM calls use `retry=False`.

## Development workflow

```powershell
python run_all.py                                  # backend :8000 + UI :5173 (installs deps on first run)
cd backend; .venv\Scripts\python.exe -m pytest -q  # API tests
.venv\Scripts\python.exe -m pytest -q ..\core\tests # core tests
cd ..\frontend; npm run build                      # typecheck + build

pwsh scripts/sync-agent.ps1                        # before running the hosted agent locally
azd ai agent run --no-client                       # hosted agent on http://localhost:8088
azd deploy                                         # deploy to Foundry (regenerate src/sql-ha-agent/uv.lock against public PyPI first)
```

On Microsoft-managed devices, PyPI is reachable only through the CFS proxy. Set
`UV_DEFAULT_INDEX=https://packagefeedproxy.microsoft.io/pypi/simple/` inline for `uv` commands, and never commit it.
